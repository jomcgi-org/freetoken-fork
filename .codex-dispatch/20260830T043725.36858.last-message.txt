Implemented the MTP verify crash fix. Working tree remains dirty with no commit or push.

### Root cause

The scheduler converts width-4 MTP verification into a prefill batch. `ParallelLMHead.forward()` therefore selected `batch.attn_metadata.get_last_indices(1)`, which is `[3]`.

`Qwen4ExpMTPHead.draft()` passed a one-row hidden tensor into that shared LM head, producing `hidden[[3]]` on shape `[1, hidden]`, the CUDA `IndexKernel` out-of-bounds assertion.

The same implicit selection also reduced target verification from four logits rows to one.

Fixed in:

- [embedding.py](/Users/jomcgi/repos/FreeToken/python/freetoken/layers/embedding.py:103)
- [nvfp4_linear.py](/Users/jomcgi/repos/FreeToken/python/freetoken/kernel/triton/nvfp4_linear.py:921)
- [mtp.py](/Users/jomcgi/repos/FreeToken/python/freetoken/models/qwen4_exp/mtp.py:197)
- [engine.py](/Users/jomcgi/repos/FreeToken/python/freetoken/engine/engine.py:1114)

MTP draft and verification now explicitly project all supplied rows. Ordinary prefill still selects only each request’s final row.
