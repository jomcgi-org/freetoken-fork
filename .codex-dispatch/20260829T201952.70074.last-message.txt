### Audit findings

1. **CPU prefill buffer: SAFE**

   Scheduler overlap runs one Python model forward at a time. CPU prefill uses blocking copies and `run_task_sync`, while decode uses separate buffers. Two prefill calls cannot concurrently reuse `_prefill_io`, so no lock was added.

2. **Staged PLE decode: FIXED**

   The staging bank did not account for an explicit CUDA graph size exceeding both `max_running_req` and `max_forward_len`. Capacity now includes the resolved padded decode maximum.

   Tests cover:

   - Pending sampled tokens with shared event deduplication.
   - Rows whose token remains in host history.
   - In-flight aborted requests.
   - Padded dummy rows.
   - Explicit graph size 8 with `max_running_req=3`.

3. **HMM PLE decode: SAFE**

   HMM consumes device-side IDs and uses the same bounds-safe gather kernel as pinned PLE. Dummy padding hashes remain valid, and the gather clamps invalid addresses before access. The CUDA graph test now uses three rows, including a stable dummy row.

4. **DISK CPU decode: SAFE**

   Tasks are cached per `(layer_id, batch_size)`. A new bs=3 test verifies two DISK layers get distinct tasks. Shared same-size IO is safe because each layer’s submit/sync sequence is stream ordered. The native callback copies all `bs * top_k` routes, then Python deduplicates their union once across the batch.

5. **Radix hit plus DISK prefill: SAFE**

   Scheduler input mapping contains only each request’s `extend_len`. Routing therefore sees the actual uncached chunk, and that exact `topk_ids` tensor is passed to DISK prefetch. Batch-wide route deduplication is tested.
